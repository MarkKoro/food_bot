# Проверка качества Food

Общая [система технических и интерфейсных правил](https://github.com/MarkKoro/progressor_core/blob/main/docs/QUALITY_PROGRAM.md) находится в Core.
Его код не переносится в Food. Еда, оценки, порции, цели и платёжные факты остаются
в собственной базе Food; общий контекст предоставляется с проверкой прав.

- Фото из обычной Telegram камеры остаётся основным вводом. Документ с изображением
  — дополнительный вариант. Проверяйте размеры, orientation, декодирование и
  понятный отказ при повреждённом изображении; не обещайте распознавание любого снимка.
- ИИ возвращает состав и nullable nutrients_per_100g по реестру. Порция и её правки
  пересчитываются арифметически. Ручные исторические нутриенты сохраняются, поля
  ручного редактора нутриентов не возвращаются в интерфейс.
- Модель не определяет cache_hit или списание. Эти признаки задаёт только сервер
  после проверки собственного кэша. JSON модели разбирается по разрешённой схеме.
- Неполный дневник не доказывает недостаточное питание или клинический дефицит.
  Ответ в Telegram содержит КБЖУ, качество оценок и только уместный доступный контекст;
  обычный просмотр и исправление граммов не вызывают ИИ повторно.
- Сохраняется историческая дата Food по Москве (UTC+3), независимо от часов телефона.
  Подпись на экране объясняет эту дату. Личные часы напоминаний задаются отдельно.
- Ошибка сохранения оставляет черновик. Второе редактирование во время первого
  сохранения не исчезает; старый ответ дня не перекрывает выбранный позже день.
- Закрытое меню не доступно по Tab; редактор и email dialog удерживают/возвращают фокус.
  Escape/Back не подтверждают платёж, введённые граммы сохраняются обычным механизмом.
- RUB и Stars имеют одинаковое оформление. Подготовка платежа на быстрый повтор
  не создаёт несколько запросов. Используется прежняя внешняя ссылка Юкассы/Stars invoice.

`requirements.txt` включает импортируемый OpenAI SDK; `constraints.txt` закрепляет
полный граф Linux/Python 3.12. Новое окружение не наследует скрытые пакеты старого venv.
Проверяйте Python tests, `tests/webapp.test.cjs` и настоящий `static/webapp/index.html`.
HTTP fixture должна отдавать JavaScript assets как JavaScript, а HTML как HTML.
Успешная браузерная эмуляция не означает проверку физической камеры Telegram.


## Независимый запуск общего интерфейса

Локальный `static/webapp/assets/progressor-bootstrap.v1.js` — точная distribution copy канонического `Core/shared/bootstrap.v1.js`. Он захватывает исходный Telegram launch и не заставляет собственные запросы бота ждать Core. Общий UI по-прежнему загружается из единственного Core асинхронно; backend Core в бот не копируется. При правке bridge обновляйте canonical и все три копии вместе: update-all сверяет байты. При cross-navigation SDK может возвращать обновлённый proof исходного бота; не переименовывайте его источник в текущий продукт. Если sessionStorage недоступен, собственный бот работает, а неподтверждённый переход не выполняется.


Payment menu consistency: three primary periods (1/6/12 months), equal RUB/Stars buttons per row, retained extra periods with a return action. Existing quotes, SKUs, receipts, native expiry and provider confirmation are unchanged. Canonical progressor_bot.py must match Core shared/progressor_bot.py. Food menus read current billing settings. Legacy callback names remain compatible.
